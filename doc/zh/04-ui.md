# 前端控制台

## 1. 前端的产品角色

`ui/` 提供的是“董事会控制台”，而不是聊天界面。它的主要职责是让操作者可以：

- 查看公司运行全貌
- 管理 agent、project、goal、issue
- 处理审批
- 查看成本、活动、收件箱
- 访问插件页面与实例设置

从产品角度看，前端的默认问题不是“我该怎么和 AI 聊”，而是“这家公司现在在做什么、谁在做、花了多少钱、我是否需要干预”。

## 2. 技术栈

前端主要由这些部分组成：

- React 19
- React Router
- TanStack Query
- Vite
- Tailwind
- 一组自建组件和适配器 UI 组件

这套技术选择服务于一个目标：快速构建复杂管理台，而不是内容站或营销页面。

## 3. 入口与顶层组织

核心入口：

- `ui/src/main.tsx`
- `ui/src/App.tsx`
- `ui/src/lib/router.tsx`

`main.tsx` 负责装配 Provider：

- `CompanyProvider`
- `LiveUpdatesProvider`
- `BreadcrumbProvider`
- `PanelProvider`
- `SidebarProvider`
- `DialogProvider`
- `ToastProvider`
- `ThemeProvider`
- 插件桥接初始化

这说明前端的状态组织围绕“公司上下文、实时更新、布局状态、插件桥接”展开。

## 4. 路由结构体现了产品结构

`App.tsx` 中的路由几乎可以直接当成功能地图来看：

- Dashboard
- Companies
- Agents / Agent Detail
- Projects / Project Detail
- Issues / Issue Detail
- Goals
- Approvals
- Costs
- Activity
- Inbox
- Routines
- Org Chart
- Company Skills
- Company Export / Import
- Plugin Manager / Adapter Manager
- Instance Settings

也就是说，UI 不是围绕“某个页面体验”组织的，而是围绕控制平面的核心业务对象组织的。

## 5. 多公司路由前缀

前端一个很关键的设计是：**路由本身带公司前缀**。

`ui/src/lib/router.tsx` 会自动把导航链接补上当前 company prefix，这样每个公司都像拥有一套自己的工作空间路径。

这件事的价值在于：

- 减少“当前操作的是哪家公司”的歧义
- 让深链接与书签更稳定
- 让 UI 心智模型更接近“一个实例、多家公司”

## 6. 页面与组件的分工

可以粗略把 UI 拆成三层：

### 页面层 `pages/`

每个主要业务对象至少有一组页面。页面负责：

- 拉取数据
- 组织版面
- 协调多个组件
- 绑定路由状态

### 组件层 `components/`

这里有很多业务组件，例如：

- `IssueDocumentsSection`
- `CommentThread`
- `LiveRunWidget`
- `AgentConfigForm`
- `ApprovalCard`
- `KanbanBoard`
- `DevRestartBanner`

这层承担的是具体交互和展示逻辑。

### API 层 `api/`

前端 API 客户端基本与后端资源对齐，例如：

- `companies.ts`
- `agents.ts`
- `issues.ts`
- `approvals.ts`
- `dashboard.ts`
- `instanceSettings.ts`

它的设计目标很明确：让页面层尽量只关心业务调用，而不关心 fetch 细节。

## 7. 实时与运行可见性

前端不是单纯的表单后台，它很重视“运行中”的信息：

- `LiveUpdatesProvider`
- `LiveRunWidget`
- Inbox 和最近活动
- Dev Restart Banner

这说明 UI 的重点不仅是维护静态配置，还包括观察 runtime 行为。

## 8. 适配器与插件在 UI 中的位置

前端不是只渲染主系统页面，它还承担了两种扩展：

### Adapter 配置界面

不同 adapter 会有自己特定的配置 schema、stdout 解析和展示方式，因此 `ui/src/adapters/` 是一个很重要的目录。

### Plugin UI 承载

Paperclip 的 plugin system 并不只扩展后端，也会把页面、tab、widget、launcher 注入前端，因此 UI 中有一整套 plugin bridge、launchers、slots 逻辑。

## 9. 如何读前端代码

推荐顺序：

1. `ui/src/main.tsx`
2. `ui/src/App.tsx`
3. `ui/src/context/CompanyContext.tsx`
4. `ui/src/lib/router.tsx`
5. `ui/src/pages/Dashboard.tsx`
6. `ui/src/pages/IssueDetail.tsx`
7. `ui/src/components/IssueDocumentsSection.tsx`
8. `ui/src/adapters/`
9. `ui/src/plugins/`

如果你是第一次接手这个前端，先理解页面结构和 company context，会比先读单个组件更有效。
