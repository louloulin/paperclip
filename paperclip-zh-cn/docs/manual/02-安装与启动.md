# 第 02 章　安装与启动

> 环境要求：**Node.js ≥ 24.11**、pnpm ≥ 9.15（仅源码运行时需要 pnpm）。
> 官方英文文档：`doc/INSTALLING.md`、`doc/DOCKER.md`、`docs/start/quickstart.md`。

## 2.1 方式一：官方安装脚本（推荐）

开源、自托管，不需要 Paperclip 账号。

```bash
curl -fsSLO https://paperclip.ing/install.sh
curl -fsSLO https://paperclip.ing/install.sh.sha256
if command -v sha256sum >/dev/null 2>&1; then
  sha256sum -c install.sh.sha256
else
  shasum -a 256 -c install.sh.sha256
fi
bash install.sh
```

安装器会：

1. 确保 Node.js 24.11 或更高版本可用；
2. 把受管（managed）的 Paperclip CLI 安装到 `~/.paperclip/cli`；
3. 启动交互式引导（onboarding）；
4. 在受支持的 Linux / macOS 上可选安装为后台服务。

> ⚠️ 校验和与脚本来自同一源站点，只能防传输/发布错误。
> 需要独立可信来源时，请使用按 release tag 或 commit 固定的 GitHub 副本。

## 2.2 方式二：非交互式托管安装

```bash
curl -fsSL https://paperclip.ing/install.sh | bash -s -- --no-prompt --no-onboard
paperclipai onboard --yes
```

管道形式要求机器上已有受支持的 Node.js、npm、npx。
**如果需要安装 Node.js，请先下载并人工审阅 `install.sh` 再执行**——不要把特权安装命令从管道里喂进去。

## 2.3 方式三：临时试用（不落盘）

```bash
npx --registry https://registry.npmjs.org paperclipai onboard --yes
```

只想看看它长什么样、又不想留下永久安装，用上面这条。

> **常见坑：私有 npm registry**
> 如果报 `E404: paperclipai`，多半是你的全局 `~/.npmrc` 指向了私有 registry（如 GitHub Packages），
> 导致 `npx` 去私有源找包。诊断：`npm config get registry`。
> 解决：显式加 `--registry https://registry.npmjs.org`。

## 2.4 方式四：隔离的手动试运行（test-drive）

已初始化并带有 CEO Agent 的临时实例，前台运行，不安装服务、不创建首条任务，
初始化成功后才打开浏览器：

```bash
ANTHROPIC_API_KEY=... npx paperclipai test-drive
OPENAI_API_KEY=... npx paperclipai test-drive --harness codex
OPENROUTER_API_KEY=... npx paperclipai test-drive \
  --harness opencode \
  --model openrouter/anthropic/claude-sonnet-4.5
```

- 每次不带 `--data-dir` 的运行都会得到一个**唯一且保留**的临时目录，启动时打印其绝对路径；
- `--data-dir <path>` 复用同一目录；`--no-browser` 不打开浏览器；
- 从已链接的 Git worktree 调用时，`test-drive` 会顺带在该 worktree 中启用任务执行。

## 2.5 方式五：源码运行（开发者）

```bash
git clone https://github.com/paperclipai/paperclip.git
cd paperclip
pnpm install
pnpm dev
```

API 服务监听 `http://localhost:3100`，内嵌 PostgreSQL 会自动创建，无需手工建库。

常用开发命令：

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 全量开发（API + UI，watch 模式） |
| `pnpm dev:once` | 全量开发，不监听文件变化 |
| `pnpm dev:server` | 仅服务端 |
| `pnpm dev:mobile` | 在 `:3101` 提供预构建 UI（手机/平板，`/api` 反代到 `:3100`） |
| `pnpm dev:both` | 同时跑 `dev` 与 `dev:mobile` |
| `pnpm build` | 构建全部包 |
| `pnpm typecheck` | 类型检查 |
| `pnpm test` | 廉价默认测试（Vitest，不含 Playwright） |
| `pnpm test:e2e` | Playwright 浏览器测试 |
| `pnpm db:generate` | 生成数据库迁移 |
| `pnpm db:migrate` | 应用迁移 |

> `pnpm test` 不包含 Playwright；浏览器用例单独跑，通常只在改相关流程或在 CI 中执行。

## 2.6 方式六：Docker

在**项目根目录**（含 `package.json` 的目录，而非 `docker/`）执行：

```bash
docker build -t paperclip-local .
docker run --rm -p 3100:3100 -v paperclip-data:/var/lib/paperclip paperclip-local
```

镜像自带常用 Agent 工具：`git`、`gh`、`curl`、`wget`、`ripgrep`、`python3`，以及 Claude、Codex、OpenCode 三个 CLI。

构建参数：

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `USER_UID` | `1000` | 容器内 `node` 用户的 UID，**建议与宿主一致**，避免挂载目录权限问题 |
| `USER_GID` | `1000` | 同上，GID |
| `CLI_TOOLS_CACHE_EPOCH` | 空 | 刷新 CLI 安装层；CI 会注入当周 ISO 周数 |
| `PAPERCLIP_BUILD_VERSION` | 空 | Git 元数据不可用时的运行时版本号 |
| `PAPERCLIP_BUILD_COMMIT` | 空 | 写入服务端构建戳与运行时环境的 commit |

```bash
docker build -t paperclip-local \
  --build-arg USER_UID=$(id -u) --build-arg USER_GID=$(id -g) .
```

官方还提供 `docker-compose.yml` 组合：内嵌 SQLite 快速启动版、PostgreSQL 全栈版、
非可信 PR 评审版、以及面向公网的鉴权版；并支持 Podman Quadlet（systemd）托管。
详见 `doc/DOCKER.md`。

> 🔴 **Docker 里的本地适配器**：`claude_local` / `codex_local` 这类适配器需要**容器内**存在对应 CLI 与凭据。
> 若只跑 API 而不挂载凭据目录，Agent 会在心跳时报「认证失败」。详见 [第 05 章](./05-接入你的-agent.md)。

## 2.7 安装布局与后台服务

- 受管安装目录：`~/.paperclip/cli`（CLI）、`~/.paperclip`（上下文与默认数据）。
- 后台服务用 `paperclipai service` 管理（安装/启动/停止/状态）。
- 更新与回滚：`paperclipai update`（可指定 canary 或 git ref）、`paperclipai uninstall`。
- 本地存储默认路径见 `paperclipai run --help` 与 `docs/cli/setup-commands.md`。

## 2.8 安装后自检

```bash
paperclipai doctor          # 环境、连接、版本、凭据体检
paperclipai run             # 直接在本机启动服务
```

`doctor` 在 `authenticated + public` 模式下会执行更严格的安全检查。
