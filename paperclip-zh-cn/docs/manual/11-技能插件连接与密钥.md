## 11.1 技能（Skill）

技能是给 Agent 的**可复用流程说明**，运行时注入，不需要重新训练模型。

### 目录结构

```
my-skill/
  SKILL.md            # 主文件，frontmatter + 正文
  references/         # 支撑细节，按需引用
  scripts/            # 可执行辅助
```

### SKILL.md 格式

```markdown
---
name: my-skill              # 唯一标识，kebab-case
description: >-
  当需要 XXX 时使用。Use when …; don't use when ….
---

# My Skill
正文……
```

frontmatter 关键字段：

- **name** —— 唯一标识；
- **description** —— **路由描述**，告诉 Agent 什么时候该用它。
  写成决策逻辑（"use when / don't use when"），**不要写成营销文案**。

### 写作实践

1. 描述写成路由逻辑；
2. 具体、可执行，Agent 不需要猜；
3. 附代码示例与真实命令，比散文可靠；
4. 一个技能聚焦一件事，别把不相关流程塞一起；
5. 支撑材料放 `references/`，别把主文件撑爆。

### 安装与分配

```bash
# 浏览随应用发布的目录技能（不改变公司状态）
paperclipai skills catalog list
# 查看元数据与文件清单
paperclipai skills catalog show <name>
# 安装到公司技能库（不自动挂到任何 Agent）
paperclipai skills catalog install <name> --company-id <id>
# 外部来源用 import
paperclipai skills import --company-id <id> --path ./my-skill
# 挂到 Agent（add 优先；replace 覆盖全量）
paperclipai skills sync <agent-id> --add my-skill
```

公司技能与 Agent 技能是两件事：**安装到公司 ≠ 分配给 Agent**。
建 Agent 时也可以直接带 `desiredSkills`，一次到位。

## 11.2 插件系统

插件是**实例级**扩展机制：进程外 worker、按能力门控的宿主服务、作业调度、工具暴露、UI 贡献。
不 fork 主仓库就能扩展。

```bash
paperclipai plugin inspect                  # 查看插件与能力
paperclipai plugin install <pkg-or-path>
paperclipai plugin install /path/to/plugin --local
paperclipai plugin enable <plugin-id>
paperclipai plugin disable <plugin-id>
paperclipai plugin uninstall <plugin-id>
```

常见插件用途：外部适配器、汉化（见 [第 16 章](./16-中文界面插件-汉化.md)）、
知识库、自定义追踪、队列、MCP 服务、GitHub 评审 bot。

写插件见 `adapter-plugin.md`；第三方适配器见 [第 05 章](./05-接入你的-agent.md)。

## 11.3 连接（Connections）与 Apps

「连接」是 Paperclip 访问外部服务的通道（GitHub、Gmail、Slack、Google Workspace、
PostHog、AgentMail、iMessage Photon、Vercel Connect、远程 MCP……）。

产品层的三个门（three-door IA）：

| 门 | 面向 | 内容 |
| --- | --- | --- |
| **Apps** | 普通用户 | 目录里的应用、授权、常用动作 |
| **Connections** | 进阶用户 | 自定义连接、远程 MCP、凭据托管 |
| **Review** | 评审场景 | PR / 任务评审 bot 与门禁 |

底层决策（内部规范，公开连接的行为以此为准）：

- **每个连接只有一个凭据权威**：默认是 Paperclip 实例保险库（第三方凭据存 `company_secrets`）；
  经审阅的远程 MCP 方法可选择 Vercel Connect 作为权威，此时 Paperclip 只存连接引用与脱敏授权元数据。
  **一个连接绝不能混用两个来源**；
- **入站保持轻量**：外部客户端调用 Paperclip 用带作用域的 token + 既有的 profile/规则，
  不另造一套权限模型；
- 新增集成前先读 `doc/connections/CONNECTOR-PLAYBOOK.md`（官方写新连接的运行手册），
  不要另起一套并行框架。

## 11.4 密钥管理

### 两个层级

- **实例密钥** —— 全实例可用；
- **公司密钥** —— 按公司隔离。

支持加密本地存储、provider 支撑的对象存储（如 AWS Secrets Manager）。

### CLI

```bash
paperclipai secrets declarations --company-id <id> --kind secret
paperclipai secrets create --company-id <id> --name anthropic-api-key --value-env ANTHROPIC_API_KEY
paperclipai secrets link --company-id <id> --name prod-stripe-key \
  --provider aws_secrets_manager --external-ref <provider-ref>
paperclipai secrets doctor --company-id <id>
paperclipai secrets migrate-inline-env --company-id <id> --apply
```

### 授权粒度

| 绑定类型 | 效果 |
| --- | --- |
| `env.*` | 注入环境变量，**同时**授予 API 读取权限 |
| `access.*` | 只授予 API 读取权限，不注入环境变量 |

选择建议：

- 每次运行适配器或其子进程都要用的值 → `env.*` 注入；
- 只在部分运行用到、体积大或结构化的值、不继承适配器环境的技能/工具 → 按需拉取。

### 读取密钥（Agent 侧）

```bash
PAPERCLIP_API_BASE="${PAPERCLIP_API_URL%/}"; PAPERCLIP_API_BASE="${PAPERCLIP_API_BASE%/api}"
curl -s -H "Authorization: Bearer $PAPERCLIP_API_KEY" "$PAPERCLIP_API_BASE/api/agents/me/secrets"
curl -s -X POST -H "Authorization: Bearer $PAPERCLIP_API_KEY" \
  "$PAPERCLIP_API_BASE/api/agents/me/secrets/github_token/value"
```

- 列表只返回元数据；取值是**无 body 的 POST**；
- **每一次取值（含失败）都会被审计**（`secret_access_events` 与 `activity_log`）；
- **绝不要把取到的值打印、落盘或粘进评论**；
- 这些端点只认**当前运行绑定的 Agent JWT**：长期 Agent key、低信任评审 Agent、
  任务桥接 key、技能测试 token 全部被拒。

### 收到凭据时的第一动作

```bash
POST /api/agents/me/secret-proposals      # 提案为 Paperclip 密钥
```

无论凭据来自用户粘贴、OAuth 回流、邮件还是别处，
**都不要**写进评论、文档、文件、任务描述或转录。
