# 第 12 章　定时例程与自动化

> 英文原文：`doc/CLI.md#Routine-Commands`、`docs/guides/board-operator/delegation.md`、
> 插件与例程相关的 API 参考。

## 12.1 例程是什么

例程（Routine）= **可重复触发的任务定义**。每次触发都会创建一条**受跟踪的执行任务**，
并唤醒例程所属的 Agent —— Agent 走正常心跳流程接手，不需要人肉启动。

这解决的是「客服、报表、社媒发布」这类周期工作。

## 12.2 触发器

| 触发器 | 说明 |
| --- | --- |
| `schedule` | cron 表达式定时 |
| `webhook` | 外部系统回调（有公开 id 与可轮换的密钥） |
| `api` | 手动通过 API 触发 |

## 12.3 控制参数

| 参数 | 作用 |
| --- | --- |
| `concurrencyPolicy` | 并发策略：上一次还没跑完时，新的触发是排队、跳过还是并发 |
| `catchUpPolicy` | 补跑策略：停机期间错过的触发是否补跑 |
| 修订历史 | 每次更新留修订，可回滚 |

## 12.4 CLI

```bash
paperclipai routine list --company-id <id> [--project-id <project-id>]
paperclipai routine create --company-id <id> --payload-json '{...}'
paperclipai routine get <routine-id>
paperclipai routine update <routine-id> --payload-json '{...}'

paperclipai routine revisions <routine-id>
paperclipai routine revision:restore <routine-id> <revision-id>
paperclipai routine runs <routine-id> [--limit 50]

paperclipai routine run <routine-id> [--payload-json '{...}']          # 手动跑一次

paperclipai routine trigger:create <routine-id> --payload-json '{...}'
paperclipai routine trigger:update <trigger-id> --payload-json '{...}'
paperclipai routine trigger:delete <trigger-id>
paperclipai routine trigger:rotate-secret <trigger-id>
paperclipai routine trigger:fire <public-id> [--payload-json '{...}']   # 从外部系统回调
```

> `paperclipai routines disable-all` 是本地维护命令，用于批量停用；
> 单数的 `routine` 命令组映射到 REST API。

## 12.5 例程 payload 示例

```json
{
  "name": "每日成本日报",
  "agentId": "<agent-id>",
  "projectId": "<project-id>",
  "goalId": "<goal-id>",
  "descriptionMarkdown": "汇总昨日成本并写一条评论，异常时 @CEO。",
  "triggers": [
    { "kind": "schedule", "cron": "0 9 * * 1-5", "timezone": "Asia/Shanghai" }
  ],
  "concurrencyPolicy": "skip",
  "catchUpPolicy": "run_latest"
}
```

## 12.6 例程 vs 任务 vs 心跳

| 概念 | 回答的问题 |
| --- | --- |
| **例程** | 这件事多久做一次、由什么触发 |
| **任务** | 这一次要交付什么 |
| **心跳** | Agent 什么时候醒来干活 |

一次例程触发 = 生成一条任务 + 唤醒一次心跳。三者分离是 Paperclip 可审计的关键：
你能看到「哪次触发、生成哪条任务、哪次心跳处理、烧了多少成本」。

## 12.7 与审批、监控配合

- 例程执行如果需要人点头，照常走审批；
- 例程跑出异常结果时，Agent 可以升级给上级（chain of command）；
- 需要「等 CI 结果再收尾」时给任务设 monitor（见 [第 07 章](./07-心跳与执行机制.md)），
  **不要**给例程加轮询。
