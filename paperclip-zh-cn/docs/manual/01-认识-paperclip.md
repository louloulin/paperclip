# 第 01 章　认识 Paperclip

## 1.1 一句话定义

Paperclip 是一个**开源的 AI Agent 编排控制平面（control plane）**：
它是「用来管理 AI 智能体为公司干活的 App」。

官方的一句类比最贴切：

> 如果 OpenClaw 是「员工」，那 Paperclip 就是「公司」。

Paperclip 本身不是一个 Agent，也不是一个 Agent 框架，更不是聊天机器人。
它是一家公司运转所需的全部基础设施：组织架构、任务系统、预算、审批、心跳调度、审计。

## 1.2 三大典型工作流

| 步骤 | 动作 | 例子 |
| --- | --- | --- |
| 01 | 定义目标 | 「把 AI 笔记应用做到 100 万美元 MRR」 |
| 02 | 组建团队 | CEO、CTO、工程师、设计师、市场，任选任意 bot 与任意 provider |
| 03 | 审批并开工 | 审策略、设预算、按下开始、从看板监控 |

注意关键词是**管理业务目标，而不是管理 Pull Request**。

## 1.3 Paperclip 解决什么问题

| 没有 Paperclip | 有了 Paperclip |
| --- | --- |
| 开着 20 个 Claude Code 标签页，不知道谁在干什么，重启全丢 | 任务以工单为单位、会话线程化、重启后状态可恢复 |
| 需要从多个地方拼上下文提醒 bot 它到底要做什么 | 上下文从任务一路向上贯通项目与公司目标，Agent 总知道「为什么做」 |
| 一堆 Agent 配置目录，自己重新发明任务管理、沟通与协作 | 开箱即用的组织架构、工单、委派与治理 |
| Agent 死循环烧掉几百美元直到打满配额才发现 | 成本按公司/Agent/项目/任务归因，超预算自动限流 |
| 客服、报表、社媒等周期任务要人肉记得启动 | 心跳与例程按计划自动执行，执行即工单 |
| 有想法 → 找仓库 → 起 Claude Code → 守着标签页 | 在 Paperclip 建一条任务，编码 Agent 自己干完，你只做验收 |

## 1.4 四大支柱

| 支柱 | 面向谁 | 覆盖内容 |
| --- | --- | --- |
| **Agentic 任务管理** | 所有人、每天 | 任务、审批与评审门禁、主动型 Agent 同事、可审计的例程与工作流、从 diff / 截图 / 测试验收 |
| **Agent 员工组织架构** | 管理者 | 人机混合组织架构、职责、委派与分工、治理（谁能做什么）、按范围授予的密钥与公司边界 |
| **Agent 员工培训** | 赋能者 | Skill Studio 与全公司共享技能、评测（evals）与测试运行、主动学习闭环与质量指标、Agent 绩效评估 |
| **Agentic OS** | IT 与平台 | 跨 provider 运行时、沙箱、集成与 MCP、SSO/GRC/RBAC/成本控制、数据隐私、内部追踪、复利式数据沉淀 |

## 1.5 系统全景

```
┌──────────────────────────────────────────────────────────────┐
│                       PAPERCLIP SERVER                       │
│  身份与访问 │ 工作与任务 │ 心跳执行 │ 治理与审批              │
│  组织架构   │ 工作区运行时 │ 插件   │ 预算与成本              │
│  例程与调度 │ 密钥与存储 │ 活动与事件 │ 公司可移植性          │
└──────────────────────────────────────────────────────────────┘
         ▲            ▲            ▲            ▲
     Claude Code   Codex      CLI agents    HTTP/web bots
```

十个系统逐条说明：

1. **身份与访问** — 两种部署模式（可信本地 / 需鉴权）、看板用户、Agent API Key、短期 run JWT、公司成员关系、邀请与接入流程。每一次写操作都能追到具体 actor。
2. **组织架构与 Agent** — Agent 有角色、头衔、汇报线、权限、预算。适配器覆盖 Claude Code、Codex、Cursor/Gemini/bash 等 CLI Agent、OpenClaw 等 HTTP/webhook bot，以及外部适配器插件。**只要能接收心跳，就能被雇佣。**
3. **工作与任务系统** — 任务带公司/项目/目标/父任务关联，签出与执行锁是原子的，一等公民的阻塞依赖，评论、文档、附件、work product、标签与收件箱状态。
4. **心跳执行** — 数据库支撑的唤醒队列，带合并（coalescing）、预算检查、工作区解析、密钥注入、技能加载、适配器调用；产出结构化日志、成本事件、会话状态与审计轨迹；孤儿运行自动恢复。
5. **工作区与运行时** — 项目工作区、隔离的执行工作区（git worktree、operator 分支）、运行时服务（开发服务器、预览 URL）。
6. **治理与审批** — 董事会审批、带评审/审批阶段的执行策略、决策记录、预算硬停、Agent 暂停/恢复/终止、完整审计。
7. **预算与成本控制** — 按公司、Agent、项目、目标、任务、provider、模型归集 token 与成本；支持告警阈值与硬停；超支自动暂停 Agent 并取消排队工作。
8. **例程与调度** — 支持 cron、webhook、API 触发的周期任务，带并发与补跑策略；每次执行都产生受跟踪的任务并唤醒对应 Agent。
9. **插件** — 实例级插件系统：进程外 worker、按能力门控的宿主服务、作业调度、工具暴露、UI 贡献。不 fork 也能扩展。
10. **密钥与存储 + 活动与事件 + 公司可移植性** — 实例/公司两级密钥、加密本地存储、对象存储、附件与 work product；所有写操作、心跳状态变化、成本事件、审批、评论、work product 都落为可审计的活动记录；整家公司（Agent、技能、项目、例程、任务）可导出导入，导入时自动脱敏与冲突处理。

## 1.6 Paperclip **不是**什么

| 不是 | 原因 |
| --- | --- |
| 聊天机器人 | Agent 有岗位，没有聊天窗口 |
| Agent 框架 | 我们不教你怎么写 Agent，教你怎么运营由 Agent 组成的公司 |
| 工作流编排器 | 没有拖拽流水线；Paperclip 建模的是「公司」——组织架构、目标、预算、治理 |
| 提示词管理器 | Agent 自带提示词、模型与运行时，Paperclip 管理它们工作的组织 |
| 单 Agent 工具 | 这是给团队用的。一个 Agent 你多半不需要 Paperclip，二十个你一定需要 |
| 代码评审工具 | Paperclip 编排工作，不评审 PR，评审流程请自备 |

## 1.7 谁应该用它

- 想构建**自主 AI 组织**的人；
- 需要**协调大量异构 Agent**（OpenClaw、Codex、Claude、Cursor）朝同一目标前进的人；
- 同时开着 20 个 Claude Code 终端、已经搞不清谁在干什么的人；
- 想让 Agent **7×24 自主运行**、但仍要能审计并在必要时插话的人；
- 需要**监控成本并强制预算**的人；
- 希望管理 Agent 的过程**像用任务管理器一样顺手**的人；
- 想用**手机**管理自己自动化业务的人。

## 1.8 它如何运行

- 本地：单个 Node.js 进程管理内嵌 PostgreSQL 与本地文件存储。
- 生产：指向你自己的 PostgreSQL，按需部署（Docker、Vercel、Kubernetes 等）。
- 一个部署可以运行**任意多个公司**，数据完全隔离。
