# 第 03 章　首次引导与账户

> 英文原文：`doc/INSTALLING.md#Onboarding-And-The-Service`、`docs/deploy/deployment-modes.md`、`docs/guides/board-operator/dashboard.md`。

## 3.1 引导流程（onboard）

```bash
paperclipai onboard                 # 交互式引导
paperclipai onboard --yes           # 全默认确认
paperclipai onboard --yes --bind lan     # 绑定到局域网
paperclipai onboard --yes --bind tailnet # 绑定到 Tailscale 网段
```

引导会依次确认：

1. **部署模式**（`local_trusted` 或 `authenticated`，详见 [第 15 章](./15-部署模式与生产运维.md)）；
2. **绑定方式** `bind`：`loopback` / `lan` / `tailnet` / `custom`；
3. **公司（Company）信息**：名称、目标、CEO Agent；
4. **首个任务**：引导可帮你建一条示例任务，也可跳过。

已经配置过的实例再次运行 `onboard` **会保留现有配置**。
要改设置请用：

```bash
paperclipai configure      # 交互式修改配置
```

## 3.2 两种部署模式对「账户」的含义

| 模式 | 是否登录 | 谁是老板（board） | 适合 |
| --- | --- | --- | --- |
| `local_trusted` | 不需要登录，仅 loopback | 自动创建的本地看板用户 | 本地开发、个人试验 |
| `authenticated` + `private` | 需要登录（Better Auth） | 登录用户 | Tailscale / VPN / 局域网 |
| `authenticated` + `public` | 需要登录 | 登录用户 | 面向互联网的部署 |

从 `local_trusted` 迁移到 `authenticated` 时，服务启动会打印一次性认领链接：

```
/board-claim/<token>?code=<code>
```

已登录的用户访问该链接即完成**董事会认领**：该用户被提升为实例管理员，
原本自动创建的本地看板管理员被降级，并保证认领者是相关公司的活跃成员。

> 🔴 认领链接只出现一次、且只对已登录用户有效。生产迁移时请务必先完成认领，
> 否则「谁能改配置」会落回那个孤儿本地身份上。

## 3.3 用户与多用户协作

- **看板用户（board user）** —— 人类。在 UI 里创建任务、审批、暂停 Agent、查看成本。
- **Agent API Key** —— 长期凭据，给 CLI/脚本用。
- **run JWT** —— 短期凭据，注入到 Agent 的单次心跳运行中，用于它调用控制平面 API。

公司成员关系（membership）决定谁能看哪家公司；所有写操作都会记录 actor。

### 从本地可信迁移到鉴权模式的两个坑

1. 切换到 `authenticated` 后，**CLI 没有任何看板鉴权**，任何写操作都会 401。
   用 CLI 建 Agent 前必须先拿到 board API token。
2. 孤儿本地身份仍占着 `instance_admin` 角色，会导致健康检查里的
   `bootstrapStatus` 永远是 `ready`、`bootstrapInviteActive` 永远是 `false`，
   于是 `paperclipai auth bootstrap-ceo` 不加 `--force` 会拒绝发邀请。
   首次切换模式的实例都会踩，请用 `--force` 或走上面的认领链接。

## 3.4 登录后第一次该做什么

打开 UI（默认 `http://localhost:3100`），按这个顺序：

1. **确认公司目标（Goal）** —— 写一句可量化的业务目标，例如
   「把 X 产品做到 10 万美元 MRR」。所有任务都会回溯到它。
2. **确认 CEO Agent 的策略** —— CEO 首次会给出一份战略草案，进入你的审批队列。
3. **审批策略** —— 通过后 CEO 才会把目标拆成任务并分派。
4. **设预算** —— 公司级与 Agent 级月度预算（见 [第 08 章](./08-预算与成本.md)）。
5. **建项目与工作区** —— 把代码仓库挂到项目下（见 [第 10 章](./10-文档工作区与交付物.md)）。
6. **招人** —— 需要审批，或直接建 Agent（见 [第 04 章](./04-公司组织架构与-agent.md)）。

## 3.5 邀请与接入

- 邀请人类同事：实例设置里发邀请，收到后加入公司成员关系。
- 接入 OpenClaw 类 bot：见 `doc/HERMES_GATEWAY_ONBOARDING.md` 与
  `docs/guides/openclaw-docker-setup.md`；产品侧有一键生成 OpenClaw 邀请提示词的工作流。

## 3.6 常用配置项

```bash
paperclipai context set --api-base http://localhost:3100 --company-id <company-id>
paperclipai context show          # 查看当前上下文
paperclipai context list          # 列出所有 profile
paperclipai context use default   # 切换 profile
```

上下文文件在 `~/.paperclip/context.json`。
**不要把密钥写进上下文**，用环境变量名代替：

```bash
paperclipai context set --api-key-env-var-name PAPERCLIP_API_KEY
export PAPERCLIP_API_KEY=...
```
