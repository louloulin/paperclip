# 第 17 章　排错与常见问题

> 本章收录安装、运行、Agent、成本四条线的高频故障与定位路径。
> 每条都给出「先看什么」的判据，而不是只给结论。

## 17.1 安装类

### `npx paperclipai` 报 `E404: paperclipai`

**真因**：全局 `~/.npmrc` 指向了私有 registry（如 GitHub Packages），`npx` 去私有源找包。

判据：`npm config get registry` 的输出不是官方源。

解决：

```bash
npx --registry https://registry.npmjs.org paperclipai onboard --yes
```

### Node 版本不满足

**真因**：需要 Node.js ≥ 24.11。

判据：报错里出现 `engines` 或 `unsupported`。

解决：用 `install.sh`（它会确保 Node 就绪），或自行安装 Node 24.11+。

### 磁盘满（ENOSPC）

**症状形态**：`failed to create a temp dir`、`could not create directory "base/…"`、
测试突然大面积 `StorageFull`，而断言本身并没有失败。

判据：**门红先 grep**：

```bash
grep -a 'os error 28\|StorageFull\|No space left' <log>
```

再去看测试断言。**清理顺序**：

```bash
df -h /
rm -rf target/debug/incremental
# deps 里每个 stem 只留 mtime 最新的产物
```

注意：同机可能有多个运行实例在写各自的 `target/`，`df` 读数会互相打架；
排查前先确认那个巨大的 `target/` 属于谁。

## 17.2 运行与鉴权类

### 切换到 `authenticated` 后 CLI 所有写操作 401

**真因**：`local_trusted` 下 CLI 靠隐式本地身份；切到 `authenticated` 后需要显式凭据。

解决：创建并使用 board key：

```bash
npx paperclipai token board create --name local-cli
export PAPERCLIP_API_KEY=<key>
```

### `bootstrapStatus` 永远是 `ready`、`bootstrapInviteActive` 永远 `false`

**真因**：从 `local_trusted` 迁移时遗留了一个占着 `instance_admin` 的孤儿本地身份，
于是 `paperclipai auth bootstrap-ceo` 不带 `--force` 会拒绝发邀请。

解决：走 [第 03 章](./03-首次引导与账户.md) 的认领链接，或 `auth bootstrap-ceo --force`。

### 502 / 504 / 服务没起来

判据顺序：

```bash
paperclipai doctor
paperclipai service status        # 后台服务模式
npx paperclipai run               # 前台跑，直接看日志
```

- 服务能起但 UI 打不开 → 看 `bind` 是否只绑了 loopback，而你从别的机器访问；
- 反代后面 → 确认上游端口与 `Host` 头，以及私有主机信任策略。

## 17.3 Agent 执行类

### Agent 一直「没登录 / 认证失败」

判据：**先确定这次运行用的是谁的凭据**（见 [第 05 章](./05-接入你的-agent.md) 的凭据归属表）。

- `codex_local`：沙箱里镜像自带的 `auth.json` **会被遮蔽**，因为 Codex 跑的是上传的 `CODEX_HOME`；
- `claude_local`：若配了 `ANTHROPIC_API_KEY` / `CLAUDE_CODE_OAUTH_TOKEN`，它们压过镜像里的登录。

### 签出时 `409 Conflict`

**真因**：任务已被另一个 Agent 拥有。**不要重试**，换一条任务。

### 任务卡在 `in_progress` 但没人动

判据：任务是否属于一次**已崩溃的运行**。

```bash
npx paperclipai issue active-run <issue-id>
npx paperclipai run live --company-id <id>
npx paperclipai issue recovery-actions <issue-id>
npx paperclipai issue recovery:resolve <issue-id> --outcome restored --source-issue-status todo
```

### 任务莫名 `blocked` 且没人恢复

**真因**：`blockedBy` 里有任务是 `cancelled` —— **cancelled 不算已解决**，不会自动唤醒。

判据：`GET /api/issues/{id}` 看 `blockedBy` 各项状态；
解决：把阻塞项改成 `done`，或从 `blockedByIssueIds` 里删掉它（传新数组会整体替换，清空传 `[]`）。

### Agent 说「我不知道该做什么」

判据：上下文是否贯通——`projectId` / `goalId` / `parentId` 是否填了。
任务只有标题没有祖先链，Agent 就只知道标题不知道「为什么」。

### 心跳不触发

依次排查：预算是否超限（100% 会硬停）、Agent 状态是否 paused/terminated、
任务是否有用户负责人（monitor 不生效）、`monitorNextCheckAt` 是否真的写进去了。

## 17.4 成本类

### 成本突然飙升

```bash
npx paperclipai costs by-agent --company-id <id>
npx paperclipai costs by-project --company-id <id>
curl "$PAPERCLIP_API_BASE/api/companies/$COMPANY/costs/summary" -H "Authorization: Bearer $PAPERCLIP_API_KEY"
```

常见真因：某个 Agent 陷入重试循环（看 run 的 event 日志）、
任务描述里有让 Agent 反复读大文件的指令、或定时例程触发过密。

### Agent 被自动暂停

**真因**：本月花费达到预算 100%，硬停。解决：提高 `budgetMonthlyCents` 或等下个日历月。
恢复命令：`paperclipai agent resume <agent-id>`。

## 17.5 文档与卡片类

### 更新任务文档一直 409

**真因**：更新时没带 `baseRevisionId`，或期间别人改过。

解决：先 `GET /api/issues/{id}/documents/plan` 拿 `latestRevisionId`，
作为 `baseRevisionId` 重发；仍冲突就再取一次最新，**不要盲重试**。

### 待确认卡片莫名消失

判据分三种：`stale_target`（计划有新修订）、`superseded_by_comment`（用户评论了）、
`issue_closed`（任务被置 `done`/`cancelled`）。三种都要**重新发起**新卡片并绑定最新修订。

### `invalid_issue_disposition`（想置 `in_review` 被拒）

**真因**：`in_review` 需要真实评审路径：交互卡片、审批、人类评审者、类型化参与者，
或**真的排期了**的 monitor（`monitorNextCheckAt` 非空）。只写一句「请评审」不算。

## 17.6 密钥类

### 取密钥 401 / 403

**真因**：端点只认**当前运行绑定的 Agent JWT**。长期 Agent key、低信任评审 Agent、
任务桥接 key、技能测试 token 全部被拒。

### 取到的密钥该不该写进评论

**永远不要。** 每次取值都会被审计。拿到新凭据的正确动作是
`POST /api/agents/me/secret-proposals`。

## 17.7 通用排障方法论

1. **先定位层级**：是安装、鉴权、执行、成本还是交付物？层级决定看哪张表。
2. **先看活动日志**：`activity list` 里有「谁、何时、改了什么」，多数疑问一次解决。
3. **先看 run 日志**：`paperclipai run log <run-id> --text`，比猜快得多。
4. **写操作先验证**：空响应体就是失败，别把退出码 0 当成功。
5. **同一写操作连续失败两次就停手**，改做别的，把失败原因写进最终汇报。
